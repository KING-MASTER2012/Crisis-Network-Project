# Protocol v1

All integers are big-endian. Only protocol version `1` exists; a decoder rejects anything else.
The reference implementation is the `proto` crate. If this chapter and the code disagree,
this chapter wins and the code is considered buggy.

## Limits

| Constant | Value |
|---|---|
| Signature | 64 bytes (Ed25519) |
| Node id | 32 bytes (Ed25519 public key) |
| Message id | 32 bytes (SHA-256) |
| Maximum `ext` | 64 bytes |
| Maximum payload | 1024 bytes (including the sealed box of a Direct message) |
| Maximum lifetime | 7 days (604 800 s) |
| Maximum hops | 16 |
| Sealed-box overhead | 48 bytes (32-byte ephemeral key + 16-byte tag) |
| Maximum encoded envelope | 1234 bytes |
| Maximum encoded frame | 1235 bytes |
| Fragment header | 10 bytes |
| Maximum fragments per frame | 255 |
| Maximum ids per `Inv` / `Want` | 15 |

## Envelope

The envelope is the signed, persistent message.

```text
version        u8      = 1
kind           u8      1=Broadcast 2=Direct 3=Ack
flags          u8      must be 0 in v1
sender         [32]    the sender's Ed25519 public key
recipient      [32]    only for Direct and Ack
created_at_ms  u64     milliseconds since the Unix epoch (sender clock, UNTRUSTED)
lifetime_secs  u32     1..=604800
ext_len        u8      0..=64
ext            [ext_len]
payload_len    u16     0..=1024
payload        [payload_len]
signature      [64]    Ed25519 over (DOMAIN_ENVELOPE_SIG || all fields above)
```

The payload of an Ack is exactly the id of the acknowledged message (32 bytes). Trailing bytes,
unknown versions or kinds, and non-zero flags are rejected.

## Message id

```text
message_id = SHA-256(DOMAIN_MSG_ID || signed body)
```

The id covers every signed byte but not the signature, so it does not depend on which valid
signature was produced.

## Domain separation

| Use | Tag |
|---|---|
| Envelope signature | `crisis/v1/envelope\0` |
| Message id | `crisis/v1/msgid\0` |

## Frame

```text
hops_left  u8   0..=16   (outside the signature: decreases on every hop)
envelope   ...
```

`hops_left` is deliberately outside the signature; otherwise every hop would invalidate it.
The message id is unaffected by `hops_left`.

## Fragment

A frame is cut into fragments that fit the link MTU.

```text
transfer_id  [8]   the first 8 bytes of the message id
index        u8    0..total
total        u8    1..=255
data         [..]  at least 1 byte
```

Fragments may arrive in any order and may be duplicated. A missing fragment, conflicting
fragments or a mismatched `total` make reassembly fail.

## Link packets

Every packet starts with a one-byte tag and must fit one transport MTU.

```text
1  Inv       count u8 (1..=15), then count x MessageId   "I have these messages"
2  Want      count u8 (1..=15), then count x MessageId   "please send me these"
3  Fragment  an encoded Fragment                          a piece of a Frame
```
